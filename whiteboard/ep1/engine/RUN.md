# Running the whiteboard engine (Linux / cloud sandbox)

Run every command from this folder (`whiteboard/ep1/engine`). README.md describes the engine itself.

## Setup (once)

```sh
npm install        # only the fonts: Caveat + Inter (@fontsource-variable). The engine has no other deps.
```

* Chrome: found automatically, in this order: `$CHROME_PATH`, Playwright's Chromium
  (`$PLAYWRIGHT_BROWSERS_PATH` or `/opt/pw-browsers`, `chromium-*/chrome-linux/chrome`, newest first;
  here it is `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`), then `/usr/bin/google-chrome` or `chromium`.
  `--no-sandbox` is added when running as root. You don't need `playwright install`.
* `ffmpeg` must be on the PATH.

## The 2-minute preview (Episode 1, a01 to b03, 0 to 127.65 s)

```sh
# 1. budget check: windows, hand time and OVER BUDGET flags per scene/part. No frames; ~3 s; missing art = MISSING
node render.js ../preview/ep1-2min.json --plan

# 2. the video (3830 frames, ~7 fps here, so ~9-10 min) -> whiteboard/ep1/preview/ep1-2min.mp4
node render.js ../preview/ep1-2min.json ../preview/ep1-2min.mp4

#    while some scenes are not drawn yet, use a stand-in for the missing SVGs:
node render.js ../preview/ep1-2min.json ../preview/ep1-2min.mp4 --placeholder test/placeholder-c11.svg

#    one section only, e.g. a06 (times are seconds in the timeline):
node render.js ../preview/ep1-2min.json ../preview/a06.mp4 --from 48.3 --to 58.05
```

* Audio: if `whiteboard/ep1/audio/ep1.mp3` exists it is muxed in (AAC 192k). Otherwise the video is
  silent (the log says `audio not found ... rendering without sound`).
* `preview/ep1-2min.json` and `preview/captions-2min.json` are generated by
  `python3 ../preview/make_preview.py` from the original `../orig/ep1-full.json` and
  `../orig/full/captions-full.json`. It points the A/B art at `../art-v2/A|B/<same file name>`, the
  a01 brandmark at `../orig/art/00-brandmark.svg`, and the hand at `hand/hand.png`. Re-run it only if those change.

## Stills (single PNG frames, no video)

```sh
node render.js ../preview/ep1-2min.json x --stills 11.5,20.5,57,96 --stills-dir ../preview/stills
```

`x` is a dummy output name. You get one `still-<t>.png` (1920x1080) per time. Add `--placeholder test/placeholder-c11.svg`
while art is missing. A good time for a still is just after a scene's `drawing ends` value in `--plan`.

## What the engine does with an art SVG (constraints for the artists)

* 1600x900 viewBox. By default the art box is the whole frame, kept above `safeBottom` 860 px, so
  1 art unit = 0.9556 px and x is offset by 195.6 px. Each SVG's own widths are used as they are
  (`<style>`, attributes or inline style): v2 line 2.6 / detail 1.5 / hatch 0.9 come out at 2.48 / 1.43 / 0.86 px.
* **Document order = drawing order.**
  * `line` paths are traced by the hand. This is also the default for any stroked path with no class.
  * `detail` paths are traced by the hand too, at 1.8x speed, with 0.04 s hops.
  * `hatch` paths are not traced: they cost no hand time. They self-draw together once the part's last
    line/detail stroke is done. Stroke i starts at partEnd + i*min(0.012, 0.35/n) and draws over 0.35 s,
    so the whole hatch burst takes at most 0.7 s.
  * The class can sit on the path or on its nearest `<g>`.
* Every sub-path (`M`) of a line/detail path is a separate stroke with its own hop. Many short sub-paths
  cost hand time; in hatch they are free.
* Fills:
  * A white fill on a stroked path (occlusion) appears as its stroke completes. An unstroked white shape
    appears when reached.
  * A colour fill on a stroked path fades in as its stroke completes, and `mix-blend-mode:multiply` works:
    lines underneath stay visible.
  * `class="accent"` / `<g id="accent">` shapes are scribbled in by the hand, which costs hand time.
* Any path syntax works (the absolute M/L/C/Q/Z rule comes from STYLE-V2/lib_v2, not from the engine).
  Dashed strokes are drawn through a mask. `<use>` is flattened. `<text>`, `<image>` and `<foreignObject>`
  cannot be drawn: they just fade in, with a warning.
* Time budget:
  * A part must finish 0.35 s before the next timed part or text in its scene.
  * A scene's drawing must end about 1.3 s before the next scene's t0 (0.55 s camera lead plus 0.75 s for the
    hand to leave).
  * The pen runs at 2200 px/s. When an item does not fit, the pen speeds up to 4000 px/s, then halves its
    pauses and goes up to 5600 px/s. `--plan` shows "natural" (calm pace) and "fastest" times, plus:
    * FAST: it fits only above 3600 px/s.
    * OVER BUDGET: it does not fit even at the fastest pace. Cut or shorten line/detail strokes, or move
      shading into hatch.
  * Tight windows in this timeline: b03-image-belongs-b (0.15 s) and -c (0.10 s) are followed at once by the
    "Caesar"/"God" texts, so keep them hatch-only or a couple of tiny strokes. a06-trap-a/b have
    1.65/1.20 s, a03 has 2.9 s and a11 has 3.4 s.
* Timeline options: `"options": { "detailSpeed": 1.8, "detailPause": 0.04, "hatchDraw": 0.35, "hatchStep": 0.012 }`.

## The hand

`hand/hand.png` (865x1660, transparent) is drawn by `hand/hand_svg.py`. It shows a right hand holding a
black marker, seen from the thumb side, with the forearm long enough to always leave the frame.

```sh
cd hand && python3 hand_svg.py && node render_png.js hand.svg hand.png   # rebuild after editing; writes hand.json
```

`hand.json` holds the nib position in PNG pixels: tip [5.2, 6.1], scale 0.78 (~23 px/cm on screen), angle 0.
`hand.orig.json` keeps the original hand's settings.
